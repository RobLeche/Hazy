# Navigation: tab bars, sheets, search

Sources (read 2026-11-26):
- Tab bars: https://developer.apple.com/design/human-interface-guidelines/tab-bars
- Sheets: https://developer.apple.com/design/human-interface-guidelines/sheets
- Searching: https://developer.apple.com/design/human-interface-guidelines/searching

## Tab bars (quoted)
- "Use a tab bar to support navigation, not to provide actions."
- "Make sure the tab bar is visible when people navigate to different sections of your app." Exception: a modal covering it.
- "Avoid overflow tabs." (A trailing "More" tab appears when space runs out.)
- "Don't disable or hide tab bar buttons, even when their content is unavailable … If a section is empty, explain why."
- "Include tab labels … Use single words whenever possible."
- "Use a badge to indicate that critical information is available" (red oval). Hazy: a badge on Outlook only for an active NWS warning.

## Sheets (quoted)
- In iOS a sheet "can be either modal or nonmodal."
- "Display only one sheet at a time from the main interface."
- "If you provide a Done button, always pair it with a Cancel button … Avoid showing all three buttons — Cancel, Done, and Back — together."
- "For complex or prolonged user flows, consider alternatives to sheets."

## Searching (quoted)
- "If search is important, give it a primary position in your app … In apps that use Tab bars … search is a dedicated tab."
- "Provide suggestions … recent searches before they start typing." "Take privacy into consideration before displaying search
  history … provide a way for people to clear it."
- "Clearly display the current scope of a search" (Hazy: the state filter, e.g. "Florida").
